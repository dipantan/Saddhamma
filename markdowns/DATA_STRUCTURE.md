# 📦 SuttaCentral Offline Data ZIP Structure 
 
This document describes the structure and optimization of the `data.zip` bundle generated by the GitHub Action pipeline. This bundle is designed specifically for the Saddhamma mobile app to ensure fast synchronization and efficient local indexing. 
 
## 📂 ZIP Hierarchy 
 
The ZIP file uses a flat structure to eliminate redundant extraction steps. All JSON files within the archive are **minified** (no whitespace). 
 
```text 
data.zip
└── data/                      # Root wrapper folder (automatically flattened by SyncService)
    ├── sutta_index.json       # Master index mapping UIDs to file paths
    ├── menus/                 # Navigation and metadata structure
    │   ├── root.json          # Top-level menu categories
    │   └── ...                # All other collection menus
    └── bilara-data-published/  # Core content folder
        ├── root/              # Pali roots
        ├── translation/       # English translations
        ├── comment/           # English comments
        ├── legacy/            # Legacy HTML fallback texts
        └── legacy_sutta_map.json # Legacy UID mapping
```

## 🚀 Optimization Details 
 
### 1. Pruning (Unused Data Removed) 
To keep the bundle size minimal (currently ~16.3 MB), the following components are **explicitly excluded**: 
- **Languages**: All non-English translations are removed. 
- **Context Data**: `html/`, `comment/`, `variant/`, and `reference/` folders are excluded. 
- **Metadata**: Author blurbs and raw metadata files are omitted. 
- **System Files**: `.git`, `node_modules`, `package.json`, and all markdown files (`.md`) are stripped. 
 
### 2. Minification 
Every `.json` file added to the zip is processed through a minifier that removes all unnecessary whitespace, comments, and formatting. This significantly reduces the payload size before compression. 
 
### 3. Maximum Compression 
The archive is generated using **JSZip** with **DEFLATE** compression at **Level 9** (Maximum). 
 
### 4. Dynamic Index Mapping 
The `sutta_index.json` at the root of the ZIP is dynamically updated during the build process. All paths in the index are transformed to use the `suttas/` prefix and forward slashes, ensuring compatibility with mobile SQLite indexing logic.

## 🛠️ Build Pipeline 
 
The bundle is created daily via the [Daily Data Sync](.github/workflows/daily-sync.yml) workflow: 
1. **Fetch**: Pulls the latest data from `suttacentral/bilara-data`. 
2. **Cleanup**: Runs `scripts/cleanup_bilara.js` to remove non-English content. 
3. **Index**: Runs `scripts/build_index.js` to generate the master mapping. 
4. **Bundle**: Runs `scripts/generate_data_bundle.js` to perform minification and create the final `data.zip`.
